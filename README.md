# Sora Lab

Sora Labは、仮説に基づく実験を繰り返し、結果を評価・記録するためのローカル研究基盤です。現在の実装は、PWS Cup 2026を対象にした合成データ生成、有用性評価、プライバシー監査に焦点を当てています。

このリポジトリに含まれるのはソースコードとテストです。大会データ、公式評価キット、生成した候補データ、実験データベース、認証情報、提出パッケージは含まれていません。プライバシー監査は開発時の比較用であり、公式な匿名性スコアや未知の攻撃への耐性を保証するものではありません。

## 動作要件・実行スペック

### 必須要件

- Python 3.10以降
- macOS。実験ランナーはPOSIXのプロセス制御を使います。LinuxやWindowsネイティブ環境での動作は確認していません。
- ローカルに配置したPWS Cup 2026の参加者向けデータ一式と公式評価キット
- 候補CSV、監査レポート、SQLite実験台帳を保存するディスク容量。保存先は利用者が指定します。
- 中核となる生成・評価処理にGPUは不要です。

### 確認済みの実行環境

- Mac：Apple M3 Max、ユニファイドメモリ64 GB
- Python 3.14.6
- Ollamaを使った任意のローカルLLM機能を含む実験環境

これは確認できている構成であり、最低要件を意味しません。コア機能単体の最小RAM量や、64 GB未満での実行可否は測定していません。そのため、未確認のCPU・RAM最低値は記載していません。コアの生成・採点ではGPUを要求しません。

### ディスク使用量の実例

この環境で確認した参加者データ一式は約1.1 MB、公式キットは約17 MBでした。複数日にわたる探索や監査を含む既存のrun rootは合計約3.3 GBを使用していました。これは個別実行の固定要件ではなく、実験を重ねると生成物と台帳が増える例です。Ollamaのモデルキャッシュは別途必要で、容量はモデルと量子化設定によって変わります。

### 任意機能

- 提案・レビュー機能：Ollamaとローカルモデル。既定のモデルは`qwen3.6:35b`です。モデル推論のメモリ・ディスク要件はモデルと量子化設定に依存します。64 GB環境で動かした構成は確認済みですが、それを最低要件とはしていません。
- Jevによる助言判断：環境変数で設定するAPI認証情報。この連携は実験状態の概要を設定先のサービスに送信しますが、元データセットは送信しません。

## 技術スタック

- PythonパッケージとCLI：`pyproject.toml`で設定
- NumPy・SciPy：数値計算、乱数サンプリング、Sobol準乱数サンプリング
- pandas：表形式データ、候補データ、スコアレポートの処理
- scikit-learn：MIA・AIAの補助攻撃の実装
- lifelines：原因別Cox比例ハザードモデル
- PyYAML：評価キットの設定ファイル読み込み
- Python標準ライブラリ：SQLite（`sqlite3`）による実験台帳、外部プロセスとHTTP連携

## 現在のシステム

### 合成データ生成（`sora_synth`）

参加者向けデータの`B.csv`、`B_self.csv`、`A_bg.csv`、スキーマ、utility参照ファイルと、公式キットの設定・採点コードをローカルパスから読み込みます。utility参照のマハラノビス距離帯を使って希少層を識別し、一般層・希少層の2成分モデルを学習します。

各成分では、参加者データと背景データを設定可能な重みで組み合わせます。連続値は重み付き周辺分位点と特徴量間の相関を推定し、ガウスコピュラ型の方法でサンプリングします。カテゴリ値は重み付きの経験確率から抽出します。発症・死亡の時刻にはそれぞれ原因別Coxモデルを用い、先に起きたイベント、または設定期間での打ち切りを候補データに付与します。乱数方式として通常の乱数とSobol方式を選べます。

単一候補の生成と、複数seedによる候補探索に対応しています。探索では共変量を固定したまま転帰を再サンプリングし、公式キットで採点できます。候補の形式を検証し、有効な候補からutilityが最も高いものを選べます。候補CSVと、入力ハッシュ・パラメータ・スコアを記録したmanifestを出力します。

### 有用性評価とプライバシー監査

有用性の評価には、指定された公式キットのvalidatorと採点関数を使います。開発用機能として、メンバーシップ推論（MIA）、属性推論（AIA）、候補と背景データの比較診断も備えています。`sora_lab`ではmember/holdout分割による監査や、許可リストに基づく攻撃仕様の進化も行えます。これらは候補同士を比較するための監査であり、公式な匿名性認証ではありません。

### 実験ランナー（`sora_lab`）

seedごとの候補生成・採点をバッチで繰り返し、セッション、実験、イベント、結果をSQLite台帳に記録します。生成物は指定したrun rootに保存します。seed範囲の再開可能な割り当て、複数ワーカー、範囲を限定したパラメータ比較、定期的なプライバシー監査に対応しています。

攻撃の進化、Ollamaによるローカルレビュー、Jevによる助言判断は任意機能です。LLMの出力は検証後に提案として扱い、任意コードの実行には使いません。LLMレビューだけを根拠に候補を自動採用することもありません。Jevは助言のみを行い、実行権限を持ちません。

このランナーは、データセットのアップロード、結果の公開、Gitへのpush、大会への提出を行いません。任意の外部連携は明示的に有効にした場合にのみネットワーク通信を行います。

## インストール

```sh
python -m venv .venv
. .venv/bin/activate
python -m pip install -e .
```

次の2つのCLIがインストールされます。

```sh
sora-synth --help
sora-lab --help
```

## 基本的な使い方

ローカルの入力データと評価キットを確認します。

```sh
sora-synth inspect --dist /path/to/participant_data --kit-dir /path/to/official-kit
```

候補を1件生成します。

```sh
sora-synth generate \
  --dist /path/to/participant_data \
  --kit-dir /path/to/official-kit \
  --out /path/to/run-root/C.csv \
  --seed 0
```

複数のseedを探索し、候補スコアを保存します。

```sh
sora-synth search \
  --dist /path/to/participant_data \
  --kit-dir /path/to/official-kit \
  --out-dir /path/to/run-root/candidates \
  --seeds 0,1,2,3
```

実験を継続して実行する場合は、データベースと生成物をソースコードの外に保存します。

```sh
sora-lab --db /path/to/run-root/lab.sqlite3 run \
  --dist /path/to/participant_data \
  --kit-dir /path/to/official-kit \
  --run-root /path/to/run-root \
  --forever \
  --batch-size 4
```

停止するときは、同じデータベースを指定して`stop`を実行します。

```sh
sora-lab --db /path/to/run-root/lab.sqlite3 stop
```

監査、再開、並列ワーカー、任意の外部連携などの設定は、各コマンドの`--help`を参照してください。

## データと出力の管理

データセット、評価キット、認証情報、モデルキャッシュ、候補CSV、レポート、実験データベースは、非公開のローカルパスに保管してください。`.gitignore`は一般的なデータファイルや実験生成物を除外しますが、公開・コミット前にはファイル一覧を確認してください。大会の入力データや認証情報を公開リポジトリに含めないでください。
